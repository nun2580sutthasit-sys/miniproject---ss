# Save & Share — ตลาดซื้อขายของมือสองสำหรับนักศึกษาทั่วประเทศไทย

เวอร์ชันนี้ต่อยอดจากเว็บไซต์เดิมและเพิ่ม REST API + PostgreSQL โดยจัดการฐานข้อมูลผ่าน pgAdmin ได้ สมัครด้วยอีเมลมหาวิทยาลัยไทยที่ลงท้าย `.ac.th` แล้วเข้าใช้งานได้ทันทีโดยไม่ต้องยืนยันอีเมล ส่วนการซื้อหรือขายยังต้องให้แอดมินตรวจสอบสถานะนักศึกษา รองรับผู้ใช้ต่างมหาวิทยาลัย การจัดส่ง และการนัดรับ

## ฟีเจอร์ในเวอร์ชันนี้

- รายชื่อมหาวิทยาลัยที่จัดการใน PostgreSQL และ API `GET /api/universities` (มีรายชื่อเริ่มต้นหลายภูมิภาค; เพิ่มสถาบันที่ยังไม่มีได้ในตาราง `universities`)
- สมัคร/เข้าสู่ระบบจริงด้วย bcrypt password hash และ JWT
- สมัครสมาชิกและเข้าสู่ระบบด้วย bcrypt password hash และ JWT; หลังสมัครระบบส่งอีเมลต้อนรับ (ไม่ใช่ OTP หรืออีเมลยืนยันตัวตน)
- ยืนยันตัวตนแบบส่งคำขอ + แอดมินตรวจสอบด้วยตนเอง
- Backend บังคับสถานะ `verified` สำหรับสร้างสินค้า สร้างคำสั่งซื้อ และเขียนรีวิว
- โปรไฟล์และสินค้าของฉันบันทึกใน PostgreSQL; อัปโหลดรูปโปรไฟล์ได้ (ระบบครอปและย่ออัตโนมัติ เก็บไฟล์ไว้ใน `backend/uploads/`) และแสดงรูปในหน้าแชท
- มีแชท REST API ที่อัปเดตทุก 3 วินาที และแจ้งเตือนข้อความ/ผลตรวจสอบ/คำสั่งซื้อใหม่/สถานะคำสั่งซื้อ
- ค้นหา/กรองสินค้าด้วยคำค้น หมวดหมู่ สภาพ ช่วงราคา การเรียง และมหาวิทยาลัยผู้ขาย
- ลงสินค้าได้สูงสุด 6 รูปต่อประกาศ; เลือก JPG/PNG/WEBP แล้วระบบย่อเป็น JPEG ก่อนบันทึกไฟล์ใน `backend/uploads/products/`
- ผู้ขายลบประกาศได้หลังยืนยัน; ถ้ามีคำสั่งซื้อแล้วระบบเก็บประกาศและแสดง `SOLD OUT` แทนการลบเพื่อรักษาประวัติ
- ผู้ใช้ทุกประเภทบัญชีที่ยืนยันแล้วสามารถลงขายสินค้าเข้า PostgreSQL ได้
- คำสั่งซื้อมีสถานะและวิธีรับสินค้า `delivery` หรือ `pickup`; หนึ่งคำสั่งซื้อต้องมาจากผู้ขายรายเดียวเพื่อให้สถานะและค่าจัดส่งไม่ปะปนกัน
- รีวิวได้เมื่อมีคำสั่งซื้อที่สำเร็จ (`completed`) กับผู้ขายนั้น
- Dashboard แอดมินดูสถิติและอนุมัติ/ปฏิเสธคำขอยืนยันนักศึกษา
- แอดมินลบสมาชิกได้ พร้อมลบสินค้า คำสั่งซื้อ รีวิว แชท และข้อมูลที่เกี่ยวข้องของสมาชิกแบบถาวร (ไม่สามารถลบบัญชีแอดมินได้)
- Postman collection สำหรับทดสอบ API

## โครงสร้างสำคัญ

- `index.html`, `pages/`, `css/`, `js/` — เว็บไซต์เดิมที่ปรับหน้าสมัครสมาชิก เลือกมหาวิทยาลัย ตัวกรองสินค้า หน้ายืนยัน และหน้าลงขาย
- `js/api-config.js` — เปิด/ปิดโหมด API
- `src/api-client.ts` — ตัวช่วยเรียก REST API ที่เขียนด้วย TypeScript
- `js/api-client.js` — ไฟล์ JavaScript ที่ build จาก TypeScript ให้หน้าเว็บใช้งาน
- `tsconfig.json` — การตั้งค่า TypeScript แบบ strict
- `backend/schema.sql` — ฐานข้อมูลใหม่และรายชื่อมหาวิทยาลัยเริ่มต้น
- `backend/migration_from_previous_mysql.sql` — สคริปต์ MySQL สำหรับฐานข้อมูลรุ่นเก่าเท่านั้น ห้ามรันกับ PostgreSQL
- `backend/src/server.js` — REST API และกฎสิทธิ์
- `backend/SaveShare_API.postman_collection.json` — collection สำหรับ Postman

## ติดตั้งบน Windows + VS Code

1. ติดตั้ง Node.js LTS, PostgreSQL และ pgAdmin (pgAdmin เป็นโปรแกรมจัดการ; PostgreSQL Server ต้องติดตั้งและเปิดทำงานด้วย) รวมถึงส่วนขยาย Live Server ใน VS Code
2. เปิด pgAdmin และเชื่อมต่อ PostgreSQL Server จากนั้นคลิกขวา **Databases → Create → Database...** ตั้งชื่อ `save_share`
3. คลิกฐานข้อมูล `save_share` แล้วเปิด **Tools → Query Tool** เปิดไฟล์ `backend/schema.sql` และกด **Execute (F5)** เพื่อสร้างตารางและรายชื่อมหาวิทยาลัย
4. เปิด Terminal ใน VS Code ที่โฟลเดอร์ `backend` แล้วรัน:
   ```bash
   npm install
   ```
   หากแก้ `src/api-client.ts` ให้ build ไฟล์สำหรับหน้าเว็บด้วยคำสั่ง:
   ```bash
   npm run build:frontend
   ```
   คำสั่งนี้จะตรวจ type และสร้าง `js/api-client.js`; หน้าเว็บยังใช้ JavaScript ที่ build แล้วตามเดิม
5. ตั้งค่าไฟล์สำหรับรหัสผ่านและค่าลับ:
   - เปิดไฟล์ `backend/.env`; ถ้ายังไม่มี ให้คัดลอก `.env.example` แล้วตั้งชื่อสำเนาว่า `.env` ในโฟลเดอร์เดียวกัน
   - แก้ค่า placeholder ใน `.env` ที่อยู่หลังเครื่องหมาย `=` อย่าใส่รหัสจริงลงใน `.env.example`
   - `PGPASSWORD` คือรหัสผ่านของผู้ใช้ PostgreSQL (`PGUSER`, ปกติคือ `postgres`) ไม่ใช่รหัสเข้า pgAdmin
   - `JWT_SECRET` ให้ใช้ข้อความสุ่มของตัวเองอย่างน้อย 32 ตัวอักษร ไม่ใช่รหัสผ่านสำหรับล็อกอิน
   - เก็บไฟล์ `.env` ไว้เป็นความลับ อย่าส่งให้ผู้อื่นหรืออัปโหลดขึ้น Git
   - หากต้องการส่งอีเมลต้อนรับหลังสมัครหรืออีเมลแจ้งคำร้อง ให้ตั้งค่า `EMAIL_PROVIDER=brevo`, `BREVO_API_KEY`, `BREVO_FROM_EMAIL` และ `BREVO_FROM_NAME` ใน `.env`; ถ้าไม่ตั้งค่า ระบบยังสมัครสมาชิกได้ แต่จะแจ้งว่าส่งอีเมลไม่สำเร็จ
6. เปิด API:
   ```bash
   npm start
   ```
   ควรเห็น `Save & Share API running at http://localhost:3000`
7. เปิด Chrome แล้วไปที่ `http://localhost:3000` เพื่อเข้าเว็บไซต์ หรือ `http://localhost:3000/api/health` เพื่อตรวจ API
8. รัน smoke test จาก Terminal อีกหน้าต่างในโฟลเดอร์ `backend`: `npm run test:smoke` ต้องผ่าน health และตรวจว่ามีรายชื่อมหาวิทยาลัยในฐานข้อมูล
9. `js/api-config.js` เปิด API จริงไว้แล้ว หาก Backend ทำงานอยู่ที่ `localhost:3000` ให้เข้า `http://localhost:3000`; หน้า Demo/localStorage ไม่ใช่โหมดหลัก
10. ถ้าเปิดหน้าเว็บผ่าน Live Server แทน ให้ตั้ง `FRONTEND_ORIGIN` ใน `.env` ให้ตรงกับ host/port ของ Live Server แล้ว restart API

### อัปเดตฐานข้อมูลเดิมสำหรับกล่องคำร้อง

ถ้าใช้ฐานข้อมูลที่สร้างไว้ก่อนหน้านี้ ให้เปิด pgAdmin → Query Tool แล้วรัน `backend/upgrade_admin_requests.sql` หนึ่งครั้ง ตารางนี้ใช้เก็บคำร้องที่สมาชิกส่งจากหน้า `pages/support.html`; ฐานข้อมูลใหม่ที่รัน `backend/schema.sql` มีตารางนี้อยู่แล้ว

### อัปเดตฐานข้อมูลเดิมสำหรับรูปสินค้า

ถ้าใช้ฐานข้อมูลเดิม ให้รัน `backend/upgrade_product_images.sql` หนึ่งครั้งใน pgAdmin → Query Tool เพื่อสร้างตารางรูปสินค้าและย้ายลิงก์รูปเดิมเข้าเป็นรูปแรก; ฐานข้อมูลใหม่ที่รัน `backend/schema.sql` มีตารางนี้อยู่แล้ว

## สร้างบัญชีแอดมิน

เปิด Terminal ในโฟลเดอร์ `backend` แล้วรันคำสั่งนี้เพื่อสร้างบัญชีแอดมิน (อีเมลแอดมินไม่จำเป็นต้องลงท้าย `.ac.th`):

```bash
npm run admin:create -- nun2580sutthasit@gmail.com
```

คำสั่งจะให้ตั้งรหัสผ่านอย่างน้อย 12 ตัวอักษรและซ่อนรหัสผ่านขณะพิมพ์ จากนั้นเข้าสู่ระบบด้วยอีเมลและรหัสผ่านที่ตั้ง แล้วเปิด `pages/admin.html` บัญชีแอดมินสร้างได้ผ่าน Terminal ในเครื่องเท่านั้น ไม่เปิด API สมัครแอดมินสาธารณะ

## ทดสอบทีละขั้น

### A. ตรวจ API และรายชื่อมหาวิทยาลัย

- เปิด `http://localhost:3000/api/health`
- เปิด `http://localhost:3000/api/universities` ต้องได้รายการมหาวิทยาลัยจาก PostgreSQL
- เข้า `pages/register.html` ตรวจว่าช่องมหาวิทยาลัยเป็น dropdown และโหลดรายชื่อจาก API

### B. สมัครและยืนยันนักศึกษา

1. สมัครด้วยอีเมลมหาวิทยาลัย `.ac.th` และเลือกมหาวิทยาลัย ระบบสร้างบัญชีและเข้าสู่ระบบให้ทันทีโดยไม่ต้องกรอกรหัส OTP
2. หากต้องการซื้อหรือขาย ให้เปิด `pages/verify.html`; กรอกรหัสนักศึกษาและส่งคำขอให้แอดมินตรวจสอบ
3. ก่อนแอดมินอนุมัติ ให้ลองใช้ API `POST /api/products` หรือ `POST /api/orders` ด้วย token บัญชีนั้น — ต้องถูกปฏิเสธด้วย HTTP 403 และรหัส `STUDENT_VERIFICATION_REQUIRED`
4. เข้าสู่ระบบด้วยบัญชีแอดมินที่สร้างไว้ แล้วเปิด `pages/admin.html` เพื่อดูสมาชิก คำขอยืนยันนักศึกษา และคำร้องจากสมาชิก
5. ในหน้าคำร้องสามารถรับเรื่อง ปิดคำร้อง หรือทำเครื่องหมายว่าดำเนินการแล้ว สมาชิกจะได้รับการแจ้งเตือนผล
6. หลังอนุมัติคำขอยืนยันนักศึกษา ให้ผู้ใช้ที่ได้รับอนุมัติออกจากระบบและเข้าสู่ระบบใหม่ แล้วลองลงขาย/ซื้ออีกครั้ง

> การยืนยันเป็น manual review สำหรับโปรเจกต์เรียน ยังไม่ได้เชื่อมระบบทะเบียนมหาวิทยาลัยหรือยืนยันโดเมนอีเมลอัตโนมัติ ห้ามใช้รหัสนักศึกษาจริงโดยไม่จำเป็นในการสาธิต

### C. สินค้าและตัวกรอง

- บัญชีที่สถานะนักศึกษาผ่านการยืนยันจากแอดมินแล้วเปิด `pages/sell.html` และเผยแพร่สินค้า (ไม่ขึ้นกับประเภทบัญชีที่เลือกตอนสมัคร)
- สินค้าจะถูกบันทึกใน PostgreSQL ผ่าน `POST /api/products`
- ไป `pages/products.html` ทดลองค้นหาคำ, หมวดหมู่, สภาพ, ราคา, เรียงลำดับ และกรองมหาวิทยาลัย
- บัญชีที่ยังไม่ยืนยันต้องไม่สามารถลงขายได้ แม้เรียก API โดยตรง

### D. คำสั่งซื้อและวิธีรับสินค้า

- เพิ่มสินค้าในตะกร้าและไป Checkout
- สินค้าที่มีผู้สั่งซื้อจะแสดง `SOLD OUT` และสั่งซื้อซ้ำไม่ได้; ประกาศที่มีประวัติคำสั่งซื้อหรือแชทจะลบไม่ได้
- เลือกจัดส่งแล้วกรอกที่อยู่ หรือเลือกนัดรับแล้วกรอกสถานที่นัดรับ
- สั่งซื้อจากสินค้าผู้ขายรายเดียวต่อหนึ่งคำสั่งซื้อ; ระบบบันทึกคำสั่งซื้อใน PostgreSQL
- ไป `pages/orders.html` เพื่อตรวจสถานะ; ผู้ขาย/แอดมินอัปเดตสถานะได้ตามสิทธิ์
- หากทดสอบผ่าน Postman ให้ใส่ `Authorization: Bearer <token>` ใน API ที่ต้องเข้าสู่ระบบ

### E. รีวิวและ Dashboard

- รีวิวต้องมีคำสั่งซื้อสถานะ `completed` กับผู้ขายรายนั้นก่อน
- เปิด `pages/admin.html` ด้วยบัญชี admin เพื่อดูจำนวนผู้ใช้ สินค้า คำสั่งซื้อ ยอดคำสั่งซื้อสำเร็จ และคำขอยืนยันที่รออนุมัติ

## API หลัก

| Method | Endpoint | รายละเอียด |
|---|---|---|
| GET | `/api/health` | ตรวจสถานะ API |
| GET | `/api/universities` | รายชื่อมหาวิทยาลัย |
| POST | `/api/auth/register` | สร้างบัญชี ส่งอีเมลต้อนรับ และคืน JWT กับ `emailSent` `{name,email,password,universityId,role}` |
| POST | `/api/auth/login` | เข้าสู่ระบบ `{email,password}` |
| GET | `/api/products?q=&category=&condition=&minPrice=&maxPrice=&sort=&universityId=` | ค้นหา/กรองสินค้า |
| GET | `/api/products/:id` | รายละเอียดสินค้า |
| POST | `/api/products` | ลงขาย (JWT + ยืนยันสถานะนักศึกษา) |
| DELETE | `/api/products/:id` | ลบประกาศของตนเองเมื่อไม่มีประวัติคำสั่งซื้อ/แชท (JWT + ยืนยันสถานะนักศึกษา) |
| GET/PATCH | `/api/me` | ดู/แก้ไขโปรไฟล์ของตนเอง |
| GET | `/api/me/products` | สินค้าของตนเอง |
| GET/POST | `/api/chats` | รายการแชท/เริ่มแชท |
| GET/POST | `/api/chats/:id/messages` | อ่าน/ส่งข้อความในห้องที่เป็นสมาชิก |
| GET/PATCH/DELETE | `/api/notifications` | ดู/ล้างการแจ้งเตือน |
| POST | `/api/verification` | ส่งคำขอยืนยัน `{studentCode,studentEmail}` |
| GET/POST | `/api/support-requests` | ดูคำร้องของตนเอง/ส่งคำร้องใหม่ |
| POST | `/api/orders` | สร้างคำสั่งซื้อ (JWT + ยืนยันนักศึกษา) |
| GET | `/api/orders` | ดูคำสั่งซื้อของตนเอง/ร้าน/แอดมิน |
| PATCH | `/api/orders/:id/status` | อัปเดตสถานะโดยผู้ขาย/แอดมิน |
| GET | `/api/reviews?sellerId=1` | อ่านรีวิว |
| POST | `/api/reviews` | เขียนรีวิวหลังคำสั่งซื้อสำเร็จ |
| GET | `/api/admin/stats` | สถิติ Dashboard (admin) |
| GET | `/api/admin/products?q=` | ค้นหาสินค้าทั้งหมด รวมสินค้าที่ซ่อน/ขายแล้ว (admin) |
| PATCH | `/api/admin/products/:id` | `{status:'active'|'hidden'}` แสดงหรือซ่อนสินค้า (admin) |
| GET | `/api/admin/users?q=` | รายชื่อและค้นหาสมาชิกทั้งหมด (admin) |
| DELETE | `/api/admin/users/:id` | ลบบัญชีสมาชิกและข้อมูลที่เกี่ยวข้องแบบถาวร (admin; ลบบัญชีแอดมินไม่ได้) |
| GET | `/api/admin/verifications` | คำขอยืนยันที่รอ (admin) |
| PATCH | `/api/admin/verifications/:id` | `{status:'verified'|'rejected',note}` (admin) |
| GET | `/api/admin/support-requests` | คำร้องจากสมาชิกทั้งหมด (admin) |
| PATCH | `/api/admin/support-requests/:id` | อัปเดตสถานะและส่งหมายเหตุให้สมาชิก (admin) |

## ส่วน Demo กับส่วน Backend จริง

- **Backend + PostgreSQL จริง:** สมัคร/เข้าสู่ระบบโดยไม่ต้องยืนยันอีเมล, โปรไฟล์, รายชื่อมหาวิทยาลัย, สมาชิกทั้งหมด, คำขอยืนยันนักศึกษา, คำร้องสมาชิก, สินค้า, คำสั่งซื้อ, รีวิว, แชท, แจ้งเตือน และ Dashboard
- **Demo/localStorage:** เมื่อ `enabled:false` หน้าส่วนใหญ่แสดงข้อมูลตัวอย่างในเบราว์เซอร์เท่านั้น ข้อมูลไม่แชร์ข้ามอุปกรณ์/ผู้ใช้ และการส่งคำขอยืนยัน Demo ไม่ถือเป็นการยืนยันจริง; ที่อยู่ กระเป๋าเงิน คูปอง และแชทไลฟ์ทดลองบันทึกไว้ในเครื่องนี้เท่านั้น
- **ยังไม่ใช่ระบบ production:** การตรวจนักศึกษายังให้แอดมินตรวจเอง, ไม่มี payment gateway/ตัดเงินจริงหรือวิดีโอไลฟ์จริง, คูปองทดลองยังไม่ถูกนำไปหักจากยอดคำสั่งซื้อ API, ไม่มีระบบรีเซ็ตรหัสผ่าน, และแชทใช้ polling (ไม่ใช่ WebSocket)
- ก่อนใช้งานจริงต้องเพิ่ม HTTPS, นโยบายข้อมูลส่วนบุคคล, logging/audit, backup, validation เพิ่มเติม, ระบบรายงาน/จัดการข้อพิพาท และตรวจความปลอดภัยโดยผู้เชี่ยวชาญ
- ฐานข้อมูล MySQL เดิมไม่ถูกแปลงหรือย้ายข้อมูลให้อัตโนมัติ; `migration_from_previous_mysql.sql` เป็นสคริปต์เก่าสำหรับ MySQL เท่านั้น ห้ามรันผ่าน pgAdmin หากต้องเก็บข้อมูลเดิม ต้องแปลงและนำเข้าข้อมูล PostgreSQL แยกต่างหาก
